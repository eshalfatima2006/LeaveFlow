Level mapping used: TCL1 = paths; TCL2 = operations; TCL3 = request media types + response media types; TCL4 = parameters + status-code classes; TCL5 = parameter values + status codes; TCL6 = response body properties; TCL7 = operation flows. Cumulative. The mapping was compared with the Lecture 20 text and Martin-Lopez, Segura and Ruiz-Cortés (A-TEST 2019); the team still decides the target.

Every covered item and its test ids are in `coverage.json` of the evidence directory.

**Counting rules.** A path, operation or parameter counts when sent in a real call; an enum value or request media type only when the operation accepted it (2xx); status codes, media types and properties when observed in a response. Operation flows are the sequences in the spec's `x-operation-flows`. A flow counts only when every step returns its documented status and meets its conditions: the decision value sent, the same request id or dates, the acting user (same user, record owner, or not the owner) and the record shown in a later read.

**Exclusions.** HEAD, OPTIONS, the HTML browsable API and 406 (framework features outside the selected scope); 405, which OpenAPI cannot document for a method that does not exist (generated and asserted, not counted); the Authorization header, which is a security scheme and not a parameter in OpenAPI (generated EP cases exist); the `/health/` probe (not a selected endpoint).

**Undocumented responses observed** (deviations, see `docs/sqe/defects/`): `decideRequest 500`, `login 500`, `submitRequest 500`.
