# SonarQube execution record

The project configuration is in `sonar-project.properties` and uses project
key `leaveflow`. Source coverage is generated by coverage.py and imported from
`coverage.xml`; SonarQube does not generate Python test coverage itself.

## Local server

The local Community container is expected at `http://localhost:9000`. The
server was verified on 24 November 2026 with `/api/system/status` returning
`UP`. The project and token must be created in the local SonarQube account
without committing either credential. The intended project default branch is
`dev`, because all ongoing work is integrated there and `main` is the final
branch.

## Scan command

After the project token is available as an environment variable, run from the
repository root:

```text
python -m coverage erase
python -m coverage run --branch -m pytest
python -m coverage xml -o coverage.xml
sonar-scanner -Dsonar.host.url=http://localhost:9000 -Dsonar.token=$SONAR_TOKEN
```

On Windows PowerShell, set the token only for the current process using the
approved local secret-handling method; do not put the token in a file, command
history, or GitHub repository. For CI, `SONAR_HOST_URL` must point to a server
reachable from GitHub-hosted runners; `localhost` only works from the local
machine.

## Required captured metrics

The final evidence must capture and interpret complexity, duplication, code
smells, bugs, vulnerabilities, coverage, technical debt, and ratings. The
manual CFG calculation for the same critical function is in
`../cfg/critical-module.md`; record the SonarQube value beside it after the
first scan and explain any convention difference.
