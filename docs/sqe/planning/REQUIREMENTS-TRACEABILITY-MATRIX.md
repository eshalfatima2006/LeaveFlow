## Conventions, evidence and status

UT=unit, API=HTTP, API-INT=integration, DT=decision table, ST=state, GEN=generator, E2E=browser flow, SEC=security, ACC=accessibility/task, PERF=load, REC=recovery, MUT=mutation, MCC=critical Boolean analysis, REG=regression. A catalog ID is defined once below, may be referenced by many requirements and can use several techniques. E2E-UCxx-01=main, -02/-03=alternatives, -04/-05=exceptions. These are30 planned flow slots, not a claim of30 passing tests; six accepted actor goals still require approval.

Evidence for each eventual implemented ID: future `docs/sqe/evidence/<area>/<run-id>/` manifest keyed by ID with actual test path/node ID, tested SHA, profile/spec/fixture/seed hashes, expected/observed, status, output/DB/browser artifacts and genuine issue URLs. No such evidence files or issue numbers are invented here. Current result/evidence for **every row** is **PLANNED / NOT MEASURED / no execution artifact**; future defect field for **every FR** is **PENDING — real issue URL when created**. This shared default applies to forward/reverse/rule/browser tables, not an omitted status.
