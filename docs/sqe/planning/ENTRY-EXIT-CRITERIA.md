# Entry, suspension, resumption and release criteria

Version0.1 — 22 November 2026. All thresholds are proposed for student/instructor review; assignment counts/full coverage remain mandatory. Future execution status is **NOT MEASURED**. Existence of a document or upstream passing test does not satisfy a team execution gate. [Risk ranking](RISK-REGISTER.md): PR-01 first, PR-02 second; **EC-01/EC-02 directly address them**.

Safe source/spec planning can continue while unrelated runtime gates are blocked; no test result may be asserted from an area that lacks its necessary entry evidence. EN criteria are distinct from final measured outcome criteria.

## Suspension and corresponding resumption

| Suspension ID / measurable trigger | Immediate action | Resumption ID / required evidence | Decision owner |
|---|---|---|---|
| SU-01: Target is not proven disposable, initial fixture differs, reset fails, or secret/real personnel data enters evidence | Stop affected stateful execution; preserve sanitized failure metadata; protect valuable DB | RS-01: isolation/target guard and two reset proofs pass; compromised credentials/data handled by students; rerun affected cases with clean contexts | A2 + peer |
| SU-02: PR-01/02 or another major integrity/security failure makes dependent experiments invalid | Preserve real response/DB state; triage; stop affected load/browser/retry paths | RS-02: approved oracle, genuine fix or safe isolated investigation condition documented; regression/denial postconditions verified before dependent experiments resume | Defect owner + independent retester |
| SU-03: Required service/tool unavailable, crash, incompatible version or missing CI job | Mark blocked, capture exit code/dependency health, continue unaffected analysis | RS-03: compatible recorded tools/health pass; failed job/case rerun on identified SHA, no success override | A1 + area owner |
| SU-04: Contradictory oracle, unapproved denominator/MCC or insufficient distinct UCs invalidates a required area | Freeze assertions/coverage claims for that area; escalate JR-03 | RS-04: real team/instructor decision recorded, versioned scope/oracle/test mapping updated and reviewed | Shared |
| SU-05: Experiment drifts from declared SHA/config/data, measurements/logs incomplete or failure state unknown | Invalidate affected run, preserve it; stop unbounded retries | RS-05: candidate/config/fixture manifest reconciled, state inspected, repeat controlled run with full evidence | Area owner + reviewer |
| SU-06: Isolated notification environment cannot be proved safe (project name or volume collision, pre-existing project resources, occupied ports, default `seed_demo` startup) | Do not start or continue UC-07 runs; preserve resource listings; touch nothing outside the run's own project | RS-06: fresh unique project with every pre-run check in [TEST-PLAN](TEST-PLAN.md#isolated-notification-environment-uc-07) passing and recorded |

Suspension is per affected activity, not an instruction to abandon all independent local work. Resumption requires causal evidence, not elapsed time or a green rerun with unexplained environment differences. Record trigger, impact, time, action and actual reviewer.

## Exit and release gates

All **10 criteria block release**. Paths below are future evidence conventions under `docs/sqe/evidence/`, not present artifacts. Each criterion needs a dated tested-SHA verdict and independent reviewer. Threshold changes require documented rationale and approval **before** execution; instructor-mandated targets cannot be reduced by team agreement. An assignment-permitted exception needs exact uncovered scope, risk, justification and actual instructor decision; proposing an exception is not passing a gate.

## Decision record template

`Candidate SHA / date / actual reviewers: PENDING; EC-ID: target above; actual: NOT MEASURED; verdict: UNEVALUATED; evidence: PENDING; open defect/risk: PENDING; corrective action and owner: PENDING.`

Current planning disposition: **HOLD — readiness not evaluated**. This is not a fabricated test failure count. Students make a final release/hold recommendation from actual evidence and residual risk; mandatory unmet/unknown criteria prevent a release-ready recommendation. Preserve prior unsuccessful candidate records, and rerun impacted gates after any source/spec/environment change.
